# consumable-forecast

消耗品ストック予測ツール — **在庫を一度も数えずに、切らさず・買いすぎずに回す**個人用ツール。

「買った」「使用開始」の記録から消費ペースを推定し、なくなる前に先回りして知らせます。

> 本ツールの予測は補助情報です。医療・在庫の正確性を保証しません。

## 特徴

- **1タップ記録**: 「買った」「使用開始」ボタンを押すだけ。押し間違えても5秒以内なら「取り消す」で戻せる。
- **在庫カウント不要**: 「使用開始」の間隔の中央値から消費ペースを自動推定。記録が少ないうちは「初期消費ペース申告」と混ぜて予測する。
- **在庫切れも安心**: 在庫0のまま使い始めても在庫はマイナスにならず、次の購入から0で数え直す。在庫切れで買い待ちした期間は学習から除外する。
- **先回り通知**: `枯渇予測日 − リードタイム − 安全マージン` を過ぎた品目を「そろそろ」リストに出し、通知する。
- **急ぐ順に表示**: ホームは「枯渇超過 → そろそろ → 余裕あり」の順。上部に件数と月あたりの出費を表示。
- **見た目でわかる**: 品目ごとの絵文字と、残り日数に応じて中身が減っていく「残量のビン」。
- **オフライン完結**: データはブラウザ内（IndexedDB）に保存。外部送信なし。
- **アプリとしてインストール**: PWA としてホーム画面に追加でき、ネットがなくても起動する。新しいバージョンが出ると「更新する」でワンタップ更新、更新後は変更点を表示する。

## 使い方

| 操作 | 内容 |
|---|---|
| **＋ 追加** | 品目を登録する。名前・アイコン（絵文字）・未開封の在庫数・単位を入力。詳細設定で1つあたりの量（例: 500 ml）、初期消費ペース、単価も設定できる |
| **買った** | 1個購入を記録。同じ日に何度押しても1件にまとまり、個数が増える |
| **使用開始** | 新しい1個を開封したことを記録。予測はこの間隔から学習する。在庫0のときは「買った」の記録漏れがないか確認する |
| **品目名をタップ** | 履歴画面を開く。日時をさかのぼった記録の追加、記録の削除、「在庫を数え直す」ができる |
| **✏（編集）** | 名前・アイコン・単位・詳細設定の変更、アーカイブ。詳細設定は空欄にすると解除される |
| **そろそろ** タブ | 補充時期の品目一覧。チェックしてまとめて「買った」を記録したり、📤 共有 で買い物リストを LINE などに送ったりできる |
| **設定** タブ | リードタイム・安全マージン、通知、データ保護、バージョン・更新の確認・インストール、エクスポート／インポート |

### 在庫の考え方

- 在庫数は**未開封の数**。「使用開始」で1減り、「買った」で増える。
- 予測では「使用中の1個 + 未開封の在庫」がなくなる日を枯渇予測日とする。
- 実際の在庫とずれたときは、履歴画面で「在庫を数え直す」を記録すると、その時点の在庫数で上書きされる。
- 使用開始の記録がまだない品目は、初期消費ペースを入れておくと、登録日を起点に暫定の予測を出す。

## セットアップ

### オフライン版（推奨）

`web/` は静的ファイルだけで動きます。`main` ブランチに push すると、GitHub Actions（`.github/workflows/deploy.yml`）で GitHub Pages に公開されます。

ローカルで試す場合:

```bash
python -m http.server 8080 -d web
# ブラウザで http://localhost:8080 を開く
```

> Service Worker と通知は `https://` か `localhost` でのみ動作します。

### サーバー版（Python）

FastAPI で `web/` を配信しつつ、SQLite に保存する REST API（`/api/*`）を提供します。

```bash
# Python 3.10+ が必要
pip install -e ".[dev]"

# 起動（PC は http://localhost:8000、スマホは表示される LAN の URL を開く）
python -m app.main
```

または

```bash
consumable-forecast
```

> 現在の画面（`web/`）は API を使わず、ブラウザ内にデータを保存します。サーバーから配信した場合も同じです。
> API は将来の同期・連携用で、絵文字・量の単位・在庫の数え直しはまだ API 側にありません。

## アプリとしてインストール

GitHub Pages など `https://` で公開した URL を開き、次のどれかでインストールします。

- Android / PC の Chrome・Edge: 設定タブの「📲 アプリとしてインストール」、またはブラウザのメニュー →「アプリをインストール」
- iPhone / iPad: Safari の共有ボタン →「ホーム画面に追加」

インストールすると、ホーム画面のアイコンからブラウザの枠なしで起動し、オフラインでも動きます。
アイコンの長押しで「そろそろリスト」を直接開くショートカットも使えます（Android）。

## バージョンアップ

### 利用者側

- アプリは起動時・画面に戻ったとき・1時間ごとに新しいバージョンを確認する。
- 見つかると画面上部に「✨ 新しいバージョンがあります」が出るので「更新する」を押す。データはそのまま引き継がれる。
- 更新後の初回起動時に、そのバージョンの変更点を表示する。
- 設定タブの「アプリについて」で現在のバージョンの確認と、手動での「更新を確認」ができる。

### リリース手順（開発者向け）

1. `web/version.js` の `APP_VERSION` を上げ、`APP_CHANGES` をそのバージョンの変更点に書き換える。
2. `pyproject.toml` と `app/main.py` の `version` も同じ番号にする（`pytest` の `test_versions_match` で確認される）。
3. `CHANGELOG.md` に追記する。
4. `main` に push すると GitHub Pages に公開され、利用者のアプリに更新のお知らせが出る。

> `APP_VERSION` を上げ忘れると、Service Worker のキャッシュが切り替わらず、利用者に新しい版が届きません。
> バージョンは [セマンティック バージョニング](https://semver.org/lang/ja/)（`メジャー.マイナー.パッチ`）で付ける。

## 通知

- 設定タブの「🔔 通知を許可する」から有効にする。「テスト通知を送る」で動作を確認できる。
- アプリを開いたときに、補充時期の品目を1日1回まとめて知らせる。通知をタップすると「そろそろ」リストが開く。
- 対応ブラウザでは、アプリアイコンに「そろそろ」の件数バッジが付く。
- iPhone では Safari の「ホーム画面に追加」から開いた場合のみ通知を使える（iOS 16.4 以降）。

## データの保護とバックアップ

データはその端末のブラウザの中だけにあります。

- 品目を登録すると、ブラウザにデータ保護（自動削除しない設定）をリクエストする。状態は設定タブで確認できる。ホーム画面に追加して使うと許可されやすい。
- 設定タブの「エクスポート (JSON)」でバックアップファイルを保存できる。一度も保存していないか、前回から30日以上たつと、ホームにお知らせを出す。
- 「インポート (JSON)」で読み込むと、今のデータは置き換わる。機種変更や別のブラウザへの移行にも使える。

## Notion連携（サーバー版・オプション）

サーバー版の API（`POST /api/items/{id}/purchases`）で購入を記録したとき、購入履歴を Notion のデータベースにも自動で転記できます。
環境変数を設定しない限り何も送信されません。

### 手順

1. Notionで [My Integrations](https://www.notion.so/my-integrations) からインテグレーションを新規作成し、シークレットキー（`secret_...`）を取得する。
2. Notion上に「消耗品購入履歴」データベースを作成し、以下のプロパティを設定する。

   | プロパティ名 | 種類 |
   |---|---|
   | 品目名 | タイトル |
   | 数量 | 数値 |
   | 購入日 | 日付 |
   | 記録元 | セレクト |
   | item_id | 数値 |

3. 作成したデータベースの「…」メニュー →「接続を追加」から、手順1で作ったインテグレーションを接続する。
4. データベースのURLから database_id を取得する（URL中の32桁のID部分）。
5. リポジトリ直下に`.env`ファイルを作成する（`.env.example`をコピーして値を埋める）。

```bash
cp .env.example .env
```

```
NOTION_TOKEN=secret_xxxxxxxx
NOTION_DATABASE_ID=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

`.env`は`.gitignore`済みなのでリポジトリにはコミットされない。アプリ起動時に自動で読み込まれる。

Notion側で障害が発生していても、送信に失敗するだけでアプリ自体は止まりません（警告ログのみ出力）。

## 開発

### テスト

```bash
pytest
```

予測エンジンは `app/forecast.py`（Python）と `web/forecast.js`（JS）の2つに同じロジックがあります。片方を変えたらもう片方も合わせてください。

### アイコンの作り直し

`tools/make_icons.py` を編集して実行すると、全サイズのアイコンを `web/` に書き出します（Pillow が必要）。

```bash
pip install pillow
python tools/make_icons.py web
```

アイコンを変えたら、`web/version.js` のバージョンを上げてください（上げないと利用者の端末のキャッシュが更新されません）。
